## 简历翻译对照表（关键，决定能不能过筛）

把游戏经验翻译成 AI 岗位能听懂的语言：

| 游戏行业说法 | 翻译成 AI 岗位说法 |
| --- | --- |
| 用 opencode + API 提效 | 搭建 LLM 辅助开发流水线，团队交付效率提升 X% |
| 做游戏服务器 | 高并发后端服务 + 状态同步 + 数据一致性 |
| C++ 做引擎/性能优化 | C++ 性能优化 / 推理部署 / 底层系统能力 |
| Unity/Cocos 做玩法 | C# 工程能力 + 复杂业务逻辑编排 |
| 美术/策划管线 | 跨职能协作、需求到落地的工程闭环 |

## 作品集三件套（面试就靠它们）

1. GitHub 仓库 + 清晰 README
2. 一张架构图（draw.io / Excalidraw）
3. 一段 3 分钟 demo 视频（录屏：上传 → 提问 → 带来源回答）

简历里写「有数据」的话最加分，例如：
> RAG 问答准确率从 72% 优化到 88%（通过调整分块策略 + 引入 rerank）

---

## 面试八股（Phase 3 第 22 周重点）

- RAG 原理：全链路每步「为什么这么做」
- 幻觉治理：怎么约束、怎么验证
- 成本优化：token 控制、缓存、模型选型
- 长上下文：如何处理超长文档
- Agent 设计：循环终止、工具调用、状态管理
- 微调选型：什么时候 RAG、什么时候微调、什么时候不用模型

## 阶段自检清单（每 8 周过一遍）

- [ ] 能不看文档，从零写一个 FastAPI + Docker 服务并跑起来？
- [ ] 能稳定让 LLM 输出结构化 JSON，并能校验它？
- [ ] 能讲清 RAG 全链路每步「为什么这么做」，以及它和微调的区别？
- [ ] 能搭一个带工具调用的 Agent，并控制它的循环终止？
- [ ] 能本地部署一个量化模型并说出显存/吞吐的权衡？
- [ ] 每个产出物都推到 GitHub 并写了能自证效果的 README？

---

## 三个最容易翻车的坑

1. 陷在数学里：Transformer/Attention 看懂流程即可，别推梯度、看论文公式。
2. 只学不产出：每周必须有东西 push 到 GitHub，否则 6 个月后简历还是空的。
3. 追求微调效果：应用岗要的是「知道什么时候用 RAG、什么时候微调、什么时候不用模型」。
