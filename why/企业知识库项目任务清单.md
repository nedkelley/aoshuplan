# 作品一：企业知识库问答系统 · 分步任务清单

> 目标：2 周（20–30 小时）做出一个能写进简历、能自证效果的项目
> 形态：上传 PDF/Word 文档 → 自动解析切片入库 → 用户提问 → 检索相关内容 → LLM 生成带引用的回答
> 建议：用 opencode 帮你起框架，但每个模块你要「看得懂 + 会改 + 能讲清」

---

## 技术选型（尽量国产/免费，练手成本低）

| 模块 | 选型 | 说明 |
| --- | --- | --- |
| 语言/框架 | Python 3.10 + FastAPI + uvicorn | 后端 |
| 文档解析 | PyMuPDF（PDF）+ python-docx（Word） | 简单够用 |
| 分块 | langchain-text-splitters | 递归字符分块 |
| 向量化 | 阿里 text-embedding-v3 或本地 BAAI/bge-small-zh | 中文效果好 |
| 向量库 | Chroma（起步）→ pgvector（进阶） | Chroma 最省事 |
| 生成 | DeepSeek / 通义千问 API（OpenAI 兼容） | 便宜好用 |
| 前端 | Streamlit | 半小时出界面 |
| 评估 | RAGAS + 自建 20 题测试集 | 量化效果 |
| 部署 | docker-compose | 一键起服务 |

## 第 1 步：搭骨架（0.5 天）

**做什么**：建目录、虚拟环境、装依赖、git init。

```
knowledge-base/
├── app/
│   ├── main.py          # FastAPI 入口
│   ├── parser.py        # 文档解析
│   ├── chunker.py       # 分块
│   ├── embedder.py      # 向量化
│   ├── store.py         # 向量库读写
│   ├── retriever.py     # 检索
│   ├── generator.py     # 生成回答
│   └── config.py        # 配置（API key 等）
├── data/                # 放测试文档
├── tests/               # 评估脚本
├── requirements.txt
└── README.md
```

**命令**：
```bash
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install fastapi uvicorn pymupdf python-docx langchain-text-splitters chromadb openai streamlit
```

**验证**：`uvicorn app.main:app --reload` 能起服务，`/docs` 能打开。

**卡点**：Windows 上 `pymupdf` 直接 `pip install pymupdf` 即可（不要装 `fitz`）。

---

## 第 2 步：文档解析模块（1 天）

**做什么**：写 `parser.py`，输入文件路径，输出纯文本（保留标题/段落结构）。

- PDF → `fitz.open()` → 逐页 `page.get_text()`
- Word → `docx.Document()` → 逐段取 `.text`
- 统一返回一个 `list[dict]`，每项 `{"page": n, "text": "..."}`

**验证**：拿一份真实 PDF（产品手册/公司制度/合同）跑通，打印看文本是否完整、没有乱码。

**卡点**：
- 扫描版 PDF（图片型）取不到文字 → 需 OCR（第 5 步再补，先用文字版 PDF）。
- 表格内容丢失 → 先接受，README 里写明「表格解析是后续优化点」。

---

## 第 3 步：分块模块（0.5 天）

**做什么**：写 `chunker.py`，把长文本切成带重叠的小块。

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter
splitter = RecursiveCharacterTextSplitter(
    chunk_size=500, chunk_overlap=50, separators=["\n\n", "\n", "。", "，", " "]
)
chunks = splitter.split_text(text)
```

**关键**：`chunk_size` 按 embedding 模型的 token 限制调（500 字左右较稳），`overlap` 保留上下文。

**验证**：打印切分结果，确认块大小合理、句子没被切断。

---

## 第 4 步：向量化 + 入库（1 天）

**做什么**：写 `embedder.py` 和 `store.py`。

- `embedder.py`：封装 embedding 调用（阿里 text-embedding-v3 用 OpenAI 兼容接口，或本地 sentence-transformers 加载 bge-small-zh）
- `store.py`：用 Chroma 存 `(文本, 向量, 元数据)`

**验证**：把第 2 步的文档切块后入库，写个脚本能 `store.query(embedding, top_k=5)` 返回相似块。

**卡点**：
- embedding 维度要一致（Chroma 首次建集合定维度，换模型要重建集合）。
- 想省钱就先本地跑 bge-small-zh（`pip install sentence-transformers`），后面再切 API。

---

## 第 5 步：检索 + 生成（1 天，核心闭环）

**做什么**：写 `retriever.py` 和 `generator.py`，串起「提问→检索→拼 prompt→生成」。

1. 用户提问 → embedding → 向量检索 top-k 块
2. 把检索块拼进 prompt（带「请基于以下资料回答，资料没有就说不确定」的约束）
3. 调 LLM 生成，要求返回答案 + 引用的来源

**prompt 模板**（关键，直接决定效果）：
```
你是一个知识库助手。仅根据下面的资料回答问题，资料中没有的内容明确说"资料中未提及"，不要编造。
资料：
{检索到的文本块}
问题：{用户问题}
请给出答案，并列出你引用的资料编号。
```

**验证**：命令行里问几个问题，看答案是否「有依据、不乱编、能指出来源」。

**卡点**：
- 答案乱编 → 加强 prompt 约束（"不要编造"）、降低 top-k、加温度=0。
- 检索不到相关内容 → 调大 top-k、换 embedding 模型、检查分块是否切碎了。

---

## 第 6 步：FastAPI 接口（0.5 天）

**做什么**：在 `main.py` 里加两个接口：

- `POST /upload`：上传文档 → 解析 → 切块 → 入库
- `POST /ask`：提问 → 检索 → 生成 → 返回 `{answer, sources}`

**验证**：用 `curl` 或 `/docs` 页面测通两个接口。

---

## 第 7 步：前端界面（0.5 天）

**做什么**：用 Streamlit 写 `app.py`（或单独目录），做上传框 + 问答框 + 来源展示。

**验证**：浏览器里能上传文档、提问、看到带来源的回答。

---

## 第 8 步：评估（1 天，简历的含金量在这）

**做什么**：写 `tests/eval.py`。

1. 手工准备 20 个「问题 + 标准答案」，覆盖你的测试文档
2. 用 RAGAS 跑评估（faithfulness / answer_relevancy / context_recall）
3. 记录分数，优化（调 chunk_size、top-k、换 rerank）后再测，对比

**产出**：一句能写进简历的话，例如「RAG 问答准确率从 72% 优化到 88%」。

**卡点**：RAGAS 需要 API key 评估，嫌麻烦可以先手写简单评估（命中关键词/人工打分）。

---

## 第 9 步：加 Rerank 优化（可选，0.5 天）

**做什么**：检索出 top-20 块后，用 rerank 模型重排取 top-5，提升精度。

- 本地：BAAI/bge-reranker-base
- 或 API：Cohere / 通义 rerank

**验证**：对比加 rerank 前后的评估分数。

## 全程防卡清单

| 症状 | 排查 |
| --- | --- |
| 取不到 PDF 文字 | 是扫描版，需 OCR（paddleocr/tesseract） |
| 答案乱编 | 加 prompt 约束、温度设 0、top-k 调小 |
| 检索不相关 | 换 embedding 模型、调整 chunk_size、加 rerank |
| embedding 维度报错 | 删掉 Chroma 旧集合重建 |
| API 报 401 | 检查 key、base_url 拼写 |
| 中文效果差 | 换中文 embedding（bge/text-embedding-v3） |
